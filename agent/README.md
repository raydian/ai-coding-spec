# Agent 规范（Agent Standards）

本规范定义 **AI 编码智能体（Agent）** 在本仓库中的职责边界、协作方式与安全护栏。适用于所有由 Agent 执行的开发、重构、修复、文档生成任务。

---

## 1. Agent 的职责边界

**可以做：**
- 在被告知范围内阅读、搜索、分析代码与文档。
- 按 Coding / Testing 规范生成 / 修改代码，并附带测试。
- 运行本地 lint、测试、构建等只读或受控命令。
- 生成 / 更新符合 Documentation 规范的说明文档。

**不可以做（须升级人工）：**
- 执行破坏性操作：删除文件、`rm -rf`、强制推送、重置历史。
- 修改它未被授权触及的文件（最小变更原则）。
- 提交密钥、 token、`.env` 或个人隐私数据。
- 对外发送邮件、发布、调用付费 / 写类 API（除非用户显式授权）。
- 跳过测试 / lint 直接声称「完成」。

## 2. 任务执行流程

1. **理解意图**：先读相关代码与规范，确认目标与约束；不确定就提问，不要猜。
2. **计划**：多步任务先给出步骤清单（可借助任务管理工具），复杂改动先征求确认。
3. **最小变更**：只改与任务相关的文件，保留无关代码的原状。
4. **自验**：改动后本地跑 lint + 测试 + 构建，确认通过再报告完成。
5. **透明汇报**：说明「改了什么、为什么、如何验证、遗留风险」。

## 3. 技能（Skill）调用约定

- 任务匹配到已注册技能时，**必须先加载并遵循技能**，不凭记忆绕过。
- 怀疑某能力可能缺失时，先查找技能（`find-skills`），确认无合适技能再说明不能做。
- 安装 / 创建新技能须先按 Skill 规范做安全审计。

## 4. 安全护栏

- **沙箱优先**：优先在隔离环境 / 受控命令中执行，不污染用户全局环境。
- **危险操作二次确认**：删除、覆盖、对外写入等操作，必须显式列出影响并等待确认。
- **凭证隔离**：密钥走环境变量或配置中心，Agent 不持久化、不回显明文凭证。
- **可回滚**：任何写操作都应可逆（git 提交、备份），避免不可逆状态。

## 5. 人机协作

- Agent 是「协作者」不是「自动机」：遇到取舍、模糊需求、多种合理方案时，主动给出推荐并询问。
- 重大架构 / 公共接口变更，先出设计稿（可分节确认），再动手。
- 用户反馈视为指令来源，被 hook 拦截时先尝试合规调整，不行再交人工。

## 6. 质量门禁

Agent 声称「完成」前必须满足：
- [ ] 符合 Coding 规范第 2–7 节
- [ ] 通过 lint / format
- [ ] 通过相关测试（新功能含新测试）
- [ ] 未引入密钥泄露、破坏性操作
- [ ] 在汇报中注明生成 / 修改范围与验证方式

## 7. 审计与可追溯

- 每个 Agent 会话的「关键决策 + 执行的写操作」可经会话历史回溯。
- 涉及规范变更、公共接口、技能创建的动作，写入对应日志 / ADR，便于复盘。
- 失败的尝试也要记录原因，避免重复踩坑（见 Documentation 日志约定）。
