# 测试规范（Testing Standards）

适用范围：前端、Java、Python 三套基础工程，以及 Agent 生成的代码。

目标：用分层测试保证行为正确、回归可控、重构安全。

---

## 1. 测试金字塔

```
        /\        E2E（少量，关键链路）
       /  \       -------------------------
      /----\      Integration（接口/服务集成）
     /------\     -------------------------
    /--------\    Unit（大量，纯逻辑/组件）
   /----------\
```

- **Unit 占 ~70%**：快、隔离、无外部依赖（mock 掉 IO）。
- **Integration 占 ~20%**：真实数据库 / 真实 HTTP 层，验证组装正确。
- **E2E 占 ~10%**：只覆盖核心用户旅程（登录、主流程），成本高、易碎。

## 2. 各栈测试框架与命令

| 栈 | 框架 | 测试文件位置 | 运行命令 |
| --- | --- | --- | --- |
| 前端 | Vitest + React Testing Library | `src/**/*.test.tsx` | `npm test` |
| Java | JUnit 5 + Spring Boot Test + MockMvc | `src/test/java/...` | `mvn test` |
| Python | pytest + httpx TestClient | `tests/test_*.py` | `pytest` |

- 测试文件命名：`*.test.ts(x)` / `*Test.java` / `test_*.py`，镜像源码包结构。
- 一个测试文件聚焦一个被测单元；用 `describe`/`class` 分组用例。

## 3. 用例编写规则

1. **AAA 结构**：Arrange（准备）→ Act（执行）→ Assert（断言）三段清晰分隔。
2. **命名表意**：`should_返回错误_当_token过期` 这类「场景+预期」命名。
3. **一个用例一个断言点**：避免一个 test 里堆 10 个 assert。
4. **不依赖执行顺序**：用例之间零耦合，可随机/并行执行。
5. **不使用真实外部服务**：数据库用内存/测试库，第三方用 mock 或录制。
6. **确定性**：禁止 `sleep(1000)` 等待；用 `waitFor` / 事件 / 轮询断言。

## 4. 覆盖率要求

| 层 | 行覆盖 | 分支覆盖 |
| --- | --- | --- |
| 核心业务逻辑 | ≥ 85% | ≥ 80% |
| 工具 / 纯函数 | ≥ 90% | ≥ 85% |
| 控制器 / 路由（薄层） | 不强制 | 不强制（由集成测试覆盖） |

- CI 中设覆盖率门禁，低于阈值阻断合并。
- **覆盖率只是信号不是目标**：不写无意义的「为了覆盖而覆盖」的测试。

## 5. TDD 约定

- 修复 Bug：先写一个会失败的回归测试（Red），再修代码（Green），最后重构。
- 新功能：鼓励先写测试再实现；至少在实现同时补齐单测。
- Agent 生成功能代码时，必须同步生成对应测试（见 Coding 规范第 8 节）。

## 6. 边界与异常测试

- 每个公开函数必须测「非法输入 / 边界值 / 异常路径」。
- 校验失败、超时、依赖不可用等场景都要有对应用例，且断言错误类型与信息。

## 7. mock 规范

- 只 mock 被测单元的直接依赖，不 mock 被测对象本身。
- mock 行为要接近真实（返回值、异常、延迟），避免「永远返回固定值」的虚假测试。
- 集成测试中尽量用真实组件，减少 mock 带来的「假绿」。

## 8. 测试数据管理

- 使用工厂函数 / fixture 构造测试数据，禁止硬编码大段 JSON。
- 测试产生的数据在 `teardown` 中清理，保证可重复运行。
