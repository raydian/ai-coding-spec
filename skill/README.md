# 技能规范（Skill Standards）

本规范定义 **技能（Skill）** 的创建、结构、命名、版本与安全审计约定。技能是可复用的「能力包」，让 Agent 在匹配场景下加载既定工作流，而非每次从零发挥。

---

## 1. 什么是技能

- 技能是一份带元信息的指令文件（通常 `SKILL.md`）+ 可选参考/脚本/资源。
- 它描述「何时用、怎么用、调用什么工具/命令、遵守什么约定」。
- 目标是把**已验证的工作流**沉淀下来，降低重复探索成本、保证一致性。

## 2. 何时应该创建技能

满足以下任一条即可考虑沉淀为技能：
- 某个多步任务被重复执行 ≥ 2 次，且步骤稳定。
- 修复了一个棘手错误，过程对其他人类/Agent 有复用价值。
- 发现某个非显然的工作流（工具版本、坑点、前置条件）值得固化。
- 需要统一团队在某领域的操作方式（如部署、发布、规范检查）。

**不应创建**一次性、含敏感信息、或已被现有技能完整覆盖的技能。

## 3. SKILL.md 结构

```markdown
---
name: <skill-id>              # 小写中划线，全局唯一
description: <一句话触发描述>  # 含场景关键词，供匹配
version: 1.0.0
---

# <技能名>

## 适用场景
（何时加载本技能，触发词）

## 前置条件
（依赖、版本、凭证、环境）

## 步骤
1. ...
2. ...

## 注意事项 / 坑点
- ...

## 参考
（references/ 下的文档或外部链接）
```

- `description` 必须包含**可检索的关键词**，否则无法被匹配。
- 步骤要具体到「命令 / 工具调用」，避免空泛口号。
- 涉及版本号、路径的要随环境更新，避免过期。

## 4. 命名与存储

- `name`：`<domain>-<action>` 风格，如 `monorepo-setup`、`pdf-export`。
- 用户级技能存 `~/.workbuddy/skills/`，项目级存 `<workspace>/.workbuddy/skills/`。
- 默认用户级；仅当团队共享才放项目级。
- 已创建技能在 frontmatter 标 `agent_created: true` 以便后续维护。

## 5. 版本与维护

- 语义化版本：`major.minor.patch`。破坏性变更升 major。
- 技能是「活文档」：每次发现过时的命令 / 工具名 / 错误，立即修正。
- 未维护的技能是负债——发现明显过期应提醒用户整理或废弃。

## 6. 安全审计（安装 / 创建前必做）

安装或导入新技能（含从市场 / URL / 文件夹）前，必须审计：
1. 读取其 `SKILL.md` 与所有 bundled 文件（`scripts/`、`references/`、`assets/`）。
2. 识别风险等级：
   - **P0**：执行删除/外发/读取凭证/远程执行等高危 → 强烈警告，需显式确认。
   - **P1**：有网络/写操作但范围可控 → 警示并确认。
   - **P2**：纯本地只读处理 → 可正常安装。
3. 向用户呈现审计结论；P0/P1 必须拿到明确同意再继续。
4. **仅审计安装环节**；加载已安装技能无需重复审计。

## 7. 与 Agent 规范的衔接

- Agent 匹配到技能必须加载并遵循，不凭记忆绕过（Agent 规范第 3 节）。
- 技能内引用的命令若涉及危险操作，技能本身应写明护栏与确认步骤。
- 技能运行后若发现改进点，回写技能（修正 / 补充前置条件）。
